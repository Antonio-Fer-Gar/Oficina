# OMP control protocols: attaching to live sessions

**Research snapshot:** 2026-10-28. Upstream source references below are pinned to `can1357/oh-my-pi` commit `ef028c5ff9ee46caf785aa28dc50584fbcc3ce52` (the `main` tree observed during research), not asserted to be a released version. Research used public documentation/source only; no credentials, local configuration, or session transcripts were read, and no active session was prompted or controlled.

## Bottom line

- **The supported attach path for an already-running interactive session is Collab, and only when that session has an active Collab room.** `/collab` starts/reprints sharing; `collab.autoStart` can publish interactive sessions automatically. `omp collab list --json` inventories active local Collab hosts, while `omp collab link <instanceId|pid> [--view]` deliberately retrieves a join URL. Listing is local-machine metadata discovery, not an inventory of every `omp.exe` or saved session. [Upstream Collab: host listing and discovery](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L64-L90), [CLI reference](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/cli-reference.md#L268-L290).
- **RPC and SDK are owned-session embedding surfaces, not attach-to-another-process APIs.** RPC starts an omp subprocess and owns its stdin/stdout JSONL channel; the SDK creates/manages an `AgentSession` in the Bun host process. Both can control their own session. Their saved-session APIs load/select history, not another TUI process's live event stream. [RPC startup](https://omp.sh/docs/rpc), [upstream RPC startup/schema](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/rpc.md#L18-L42), [SDK](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/sdk.md#L1-L8).
- **Capability fit:** Collab can group shared sessions by working directory, show live status/transcript and subagents, accept prompts and interrupts, and let full-control guests answer certain host UI requests. Guest `/model` and other machine/session commands remain host-only. RPC supports `set_model`, prompt/steer, events, and subagent commands—but only against the RPC process's session. [Collab permissions](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L128-L144), [RPC command schema](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/rpc.md#L128-L171).

**Local version/result (from the parent agent's read-only check):** installed `omp.exe` reports `18.13.2`; its help exposes `collab list --json` and `collab link`. `omp collab list --json` returned `{version: 1, hosts: []}` despite omp.exe processes being present. Thus the current local processes did not advertise Collab hosts to attach to. A process count is not a session count and does not make an unshared interactive session attachable.

## What each surface actually attaches to

| Surface | Can it attach to a currently running interactive TUI? | Transport / scope | Relevant controls and limits |
| --- | --- | --- | --- |
| **RPC (`--mode rpc` / `rpc-ui`)** | **No documented process-attach API.** It starts a child omp process and communicates over that child's stdio. | Newline-delimited JSON over the process's stdin/stdout; stderr is separate. Not JSON-RPC 2.0 and not a TCP server. | `get_state`, event stream, prompt/steer/follow-up/abort, `set_model`, model discovery, and subagent snapshot/events/actions are exposed on this worker. `open_session` in current upstream takes a `sessionDir` and continues the newest non-empty saved session (or starts one); source implements this by finding the session file and switching the worker's `AgentSession`. It is not an address for a live TUI. | **SDK (`@oh-my-pi/pi-coding-agent`)** | **No documented process-attach API.** It runs in-process in a Bun application and creates the session that application owns. | Direct TypeScript/JavaScript APIs in the same process; upstream SDK docs require Bun (current upstream says Bun 1.4.4+; it is not a Node SDK). | Typed prompt/steer/follow-up/abort, event subscription, state/model/session controls. `SessionManager.list`, `continueRecent`, and `open` operate on persisted session entries/files; `open(filePath)` loads a session file. They do not provide a handle to another omp process. [SDK model](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/sdk.md#L1-L8), [session manager and open/list helpers](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/sdk.md#L62-L145), [`SessionManager.open`](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/session/session-manager.ts#L4360-L4405). |

### Collab discovery, status, and capability security

- `omp collab list` and `/collab list` enumerate live Collab hosts under the same omp configuration root across terminals, projects, and profiles. The JSON/list row includes stable `instanceId`, room generation, PID, session ID/name, `cwd`, model, start time, participant count, relay state, waiting host-input flag (`inputRequired`), turn state (`busy`), and maximum published access. The `cwd` allows a UI to group shared sessions by project path. Empty is a successful result. It does **not** list remote hosts or retain stopped rooms. [Listing contract](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L71-L90).
- The CLI deliberately separates inventory from capability retrieval: `list --json` returns metadata only, while `collab link` fetches one control URL or `--view` URL from that exact host generation. Source exposes `runCollabListCommand`, `runCollabLinkCommand`, `listCollabHosts`, and `resolveCollabHostLink`. A stale generation is rejected rather than returning a successor room's link. [CLI implementation](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/cli/collab-cli.ts#L35-L96), [registry implementation](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/collab/registry.ts#L669-L735).
- The IPC registry lives under the profile-independent config root at `run/collab-hosts`. It stores endpoint metadata and a random bearer token, not the room key, write token, or full URL; endpoint requests authenticate with that token. On Windows the registry/config-root ACL is inherited (there is no POSIX owner/mode check), so that root must remain private to the user. [Registry contract and path](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/collab/registry.ts#L1-L24), [path](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/collab/registry.ts#L157-L164), [Windows ACL behavior](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/collab/registry.ts#L363-L378).
- Full-control and view-only URLs are bearer secrets: anyone holding a valid URL gets its rights; there is no account-based identity or approval prompt. Full-control can cause the host agent to act under the host's tools/approval policy. Payloads are end-to-end encrypted with AES-256-GCM, but a full link is still a powerful host capability and a view link can reveal sensitive history. [Official security guidance](https://omp.sh/docs/collab#permissions-and-security), [upstream permission model](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L128-L171).
- `busy` is a useful activity indicator, not a durable “all work is finished” signal: upstream notes it can be false during scheduling pauses, queued follow-ups, async-job waits, and compaction. The UI should also account for unknown/null values and the host's `inputRequired` state. [Status caveat](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L81-L90).

### Limits against the requested desktop behavior

- **All sessions:** Collab can cover all *interactive* sessions only if each publishes a room (manual `/collab`, or `collab.autoStart = view|control`). Default auto-start is off. An unshared live TUI is not made discoverable by the presence of a session JSONL file or an `omp.exe` process. [Auto-start and registry scope](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L50-L58), [settings](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L150-L164).
- **Send tasks / subagents:** Full-control Collab guests can submit prompts, interrupt, and use Agent Hub to inspect/message/stop/revive host subagents; guests see the shared transcript and live activity. These are real host-side actions, not a read-only copy. [Guest rights](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L132-L145).
- **Model change:** There is no built-in guest model-selection control; `/model` is host-only. RPC `set_model` exists but affects the RPC worker only, not an unrelated TUI. [Collab host-only commands](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L144-L145), [RPC `set_model`](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L2502-L2510).
- **Human decisions:** Writable guests can answer supported host select/editor requests; view-only guests cannot. This does not make the guest a general remote shell or allow arbitrary host slash commands. [Guest permissions](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L132-L145).
- **Terminal safety:** `omp join` requires an interactive terminal. Joining from an omp TUI sets that guest's local session aside and restores it on `/leave`; it does not change the guest to the host's working directory. A browser guest avoids commandeering the user's foreground terminal and needs no omp install. [Official Collab join guide](https://omp.sh/docs/collab#join-a-session), [browser guest guide](https://omp.sh/docs/collab#from-a-browser).
- **Windows:** The official site declares Windows support. Current upstream Collab discovery uses named pipes rather than TCP on Windows; Windows inherits the omp config root ACL, which must be private. RPC source also has a Windows-specific stdout pipe writer because Bun's piped stdout could otherwise block the worker if the client stops reading. [Official platform metadata](https://omp.sh/), [Collab IPC/security](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/collab.md#L88-L90), [RPC Windows pipe handling](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L1403-L1408). The website's Collab docs say a browser is the alternative when `omp join` cannot run in a TTY: [troubleshooting](https://omp.sh/docs/collab#troubleshooting).

## Documentation/version caveat

The live `omp.sh` pages are behind the observed upstream `main` snapshot on these details: website `/docs/collab` and `/docs/cli` do not describe the `collab list` / `collab link` local registry commands; website `/docs/rpc` does not show the newer `open_session` payload. Upstream `docs/collab.md`, `docs/cli-reference.md`, and `docs/rpc.md` at the pinned commit do. The locally installed 18.13.2 help also includes Collab list/link per the parent check, so use the installed `omp --help` as the authority for exact local command syntax rather than assuming the website schema and current upstream `main` are version-identical. [Website CLI](https://omp.sh/docs/cli), [website RPC](https://omp.sh/docs/rpc), [website Collab](https://omp.sh/docs/collab), [upstream CLI](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/cli-reference.md#L268-L290), [upstream RPC](https://github.com/can1357/oh-my-pi/blob/ef028c5ff9ee46caf785aa28dc50584fbcc3ce52/docs/rpc.md#L370-L384).

## Safe no-model smoke recommendation

1. On the target Windows machine, run only `omp collab list --json`. This is a read-only metadata inventory and does not print control/view URLs or run a model. `hosts: []` means **no discoverable active Collab host**, not “no omp processes” and not “no saved histories.” That is the current local result reported above.
2. Do not run `omp collab link` against a real user's host merely to test discovery: it emits a bearer URL. For an actual UI attach smoke, use a disposable, secret-free interactive host with a **view-only** Collab room and no prompt; join through the browser, verify project/model/activity/transcript/subagent presentation, then stop the throwaway room. Do not send a prompt or test model changes. If only the RPC wire needs a smoke, an owned ephemeral RPC child with `get_state` and no `prompt` is also model-free, but it does not test attachment to a running TUI.
